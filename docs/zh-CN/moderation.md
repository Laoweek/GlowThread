# 管理指南

本指南面向管理员，即拥有 `glowthread-moderate` 权限的用户（默认为 `sysop` 用户组）。它介绍在哪里操作、每个操作的作用，以及如何快速清空队列。界面标签按简体中文界面中的文字引用。

站点管理员：权限、限制和设置见[配置](configuration.md)。

## 在哪里操作

| 位置 | 用途 |
|---|---|
| 页面的评论区 | 一边阅读一边处理评论，以及把页面的评论在开放、锁定和关闭之间切换 |
| **Special:评论管理**（“评论管理”） | 整个维基中被举报、待审核和已删除评论的队列，批量操作，键盘快速处理，作者或页面的记录，设置和敏感词 |
| **Special:Log/glowthread**（“评论日志”） | 每一次管理操作的历史 |

每个操作都会以你的名字记录在 Special:Log/glowthread 中。大多数操作在执行后可以立即撤销。

## 评论状态

| 状态 | 标签 | 谁能看到 |
|---|---|---|
| 公开 | （无标签） | 所有人 |
| 待审核 | “待审核” | 作者（“仅你可见 · 等待审核”）和管理员 |
| 已删除 | “已隐藏” | 只有管理员。可以恢复 |
| 已抹除 | “已抹除” | 管理员能看到这里曾有一条评论。文字已被永久删去。只有拥有 `glowthread-erase` 的用户能看到作者 |

评论被删除、转入待审核或抹除后，显示在它下面的回复对读者也会消失。评论恢复或通过后，这些回复会重新出现。

### 评论为何进入待审核

满足以下任一条件时，评论会进入待审核，而不会被拒绝。管理员会在“待审核原因：”后面看到原因。

| 原因 | 标签 |
|---|---|
| 敏感词规则中的某一行命中 | “命中敏感词” |
| 敏感词规则中的某条规则在这段文字上运行出错 | “敏感词检查出错” |
| 某个链接在 SpamBlacklist 中 | “链接在黑名单中” |
| 账号是新账号（新账号审核） | “新账号” |
| 多位老用户举报了它 | “多人举报” |
| 它回复的是作者自己仍在待审核的评论 | “回复的评论还在待审核” |

默认情况下，一位作者最多可以有 3 条评论等待审核。在管理员审核这些评论之前，其他本应进入待审核的评论会被拒绝。

## 在评论区内

作为管理员，你在每个评论区中会看到更多内容：

- 待审核和已删除的评论，带有它们的标签、进入待审核的原因（“待审核原因：”），以及被举报的理由，并以“由 … 举报”列出举报人的名字。
- 评论上方的管理栏。

### 管理栏

| 控件 | 作用 |
|---|---|
| 带数量的“待审核” | 只显示本页待审核的评论。再次点击显示全部 |
| 带数量的“被举报” | 只显示本页有未处理举报的评论 |
| “页面：”菜单（“本页评论”） | 确认后把页面在“开放”、“锁定”和“关闭”之间切换。见[页面状态](#页面状态) |
| “管理模式” | 开启选择：每条评论旁出现一个复选框，并出现针对所选评论的“批量管理”。“退出”关闭选择 |

### 评论菜单

打开评论的“更多操作”菜单。在“管理”下面，它会列出适用于这条评论的操作：

| 菜单项 | 适用于 | 作用 |
|---|---|---|
| “置顶”/“取消置顶” | 公开的顶层评论 | 把评论显示在最前面，位于其他评论之上，并标为“置顶” |
| “通过” | 待审核的评论 | 公开这条评论，并关闭它未处理的举报。之后的举报不会再让它自动转入待审核。会通知作者 |
| “忽略举报” | 有未处理举报的评论 | 保持评论不变，关闭它的举报。之后的举报不会再让它自动转入待审核 |
| “隐藏” | 公开和待审核的评论 | 删除这条评论：对读者隐藏。它未处理的举报会以“成立”关闭。会通知作者 |
| “恢复” | 已删除的评论 | 把评论恢复到删除前的状态。评论重新公开时会通知作者 |
| “查看用户记录” | 作者未被隐藏的所有评论 | 打开 Special:评论管理，显示这位作者的全部评论和记录 |

恢复菜单项的标签会变化，说明将会发生什么：

- “恢复”：评论重新公开。
- “恢复为待审核”：评论是在待审核时被删除的，所以会回到待审核队列。恢复操作永远不会公开未经审核通过的文字。
- “恢复并公开”：评论曾经处于待审核状态，而删除时没有记录它之前的状态（例如切换到 GlowThread 之前的删除）。恢复会让它直接公开，不经审核。

抹除只在 Special:评论管理 中提供。

### 撤销

执行操作后，屏幕底部会出现一条确认消息，带有“撤销”按钮。撤销会准确还原该操作所改变的内容：状态、设置状态的人和时间，以及它关闭的举报。如果评论在此期间被改动，撤销会失败并显示一条消息。通过、隐藏、恢复、置顶、取消置顶和忽略举报都可以撤销。抹除不能撤销。

撤销不会发送通知。收到过删除通知的作者，在删除被撤销时不会收到通知。

按 `F8` 可以移到最新的消息，用键盘使用其中的“撤销”按钮。

## 管理中心：Special:评论管理

管理中心有一个侧边菜单：“队列”、“设置”、“评论日志”、“敏感词页面”和“键盘快捷键”。

### 队列

| 分类 | 显示 | 默认排序 |
|---|---|---|
| “被举报” | 有未处理举报的公开或待审核评论 | “举报最多” |
| “待审核” | 等待审核的评论，以及原因 | “最新” |
| “已删除” | 已删除和已抹除的评论 | “最新” |
| “全部” | 所有评论 | “最新” |

队列和记录只显示你能阅读的页面上的评论。被监督删除的页面上的评论，只对能查看被监督修订的用户显示。分类上的数量包括所有评论。

缩小列表范围：

- “搜索评论文字”查找评论中的文字。它不搜索作者、页面标题或举报说明。
- “筛选”会打开“页面”和“作者”字段。作者可以是用户名或 IP 地址。
- “排序”可以在“举报最多”、“最新”和“最早”之间切换。
- 如果某位举报人提交了列表中的许多举报，会显示一个徽章（“本列表举报 N 条”）。点击它只显示这个人的举报（“举报人：…”）。有人在短时间内举报大量评论时，这很有用。

你工作时如果有新内容进来，会出现“有 N 条新内容 · 刷新”按钮。列表不会自己跳动。

每一项显示评论、作者及其注册时长（“注册 3 天”）和封禁情况、页面、它回复的评论，以及举报的理由和说明。对于因敏感词进入待审核的评论，这一项会显示命中的行（“命中第 3 行（…）”）。如果转入待审核时没有记录命中的行，拥有 `glowthread-configure` 的用户可以点击“查看命中的规则”，用当前规则测试这条评论。“查看上下文”会在页面上打开这条评论。从 FlowThread 导入的举报会显示理由，但不显示举报人。

每一项的按钮：

| 按钮 | 按键 | 适用于 | 作用 |
|---|---|---|---|
| “通过” | `a` | 待审核的评论 | 公开评论并关闭它的举报 |
| “通过” | `a` | 有举报的公开评论 | 保留评论并关闭它的举报 |
| “删除” | `d` | 公开和待审核的评论 | 隐藏评论。它的举报会以“成立”关闭 |
| “恢复” | `r` | 已删除的评论 | 恢复到删除前的状态（标签见[上文](#评论菜单)） |
| “忽略举报” | | 有举报的待审核评论 | 关闭举报，评论保持待审核 |
| “抹除…” | | 已删除的评论 | 永久抹除评论，见[抹除](#抹除) |
| “置顶”/“取消置顶” | | 公开的顶层评论 | 与评论区中相同 |

### 批量操作

勾选多个项目的复选框，或者使用“全选已加载”。这时会出现一个操作栏，包含“通过”、“删除”、“恢复”和“忽略举报”。某个操作只适用于部分所选评论时，按钮会显示适用的数量。“取消选择”（或 `Esc`）清空所选内容。

一条消息确认整批操作，并提供一个针对整批的“撤销”。如果其他管理员先改动了其中某条评论，消息会说明这一点，并且不处理那条评论。

### 用键盘快速处理

在队列中按 `?` 可以查看快捷键。

| 按键 | 操作 |
|---|---|
| `j` | 下一条评论 |
| `k` | 上一条评论 |
| `x` | 选中或取消选中当前评论 |
| `a` | 通过：公开待审核的评论，或保留被举报的评论并关闭其举报 |
| `d` | 删除 |
| `r` | 恢复已删除的评论 |
| `/` | 搜索评论文字 |
| `?` | 显示快捷键 |
| `Esc` | 取消选择 |
| `F8` | 跳到最新的消息，以便使用“撤销” |

- `a`、`d` 和 `r` 作用于所选评论。没有选中任何评论时，它们作用于当前评论。如果键盘焦点位于一条未被选中的评论内，它们只作用于这条评论。
- 在“被举报”、“待审核”和“已删除”分类中，评论在操作后会离开列表，下一条成为当前评论，所以你可以用 `j`、`a` 和 `d` 逐条处理整个列表。
- 在输入框中打字时、对话框或菜单打开时，或按住 Ctrl、Alt 或 Cmd 时，字母键不起作用。按住按键时只有 `j` 和 `k` 会重复触发，操作键永远不会。
- 在记录面板中操作时，`x`、`a`、`d` 和 `r` 不起作用。

快速处理举报的一种方式：打开“被举报”，评论没问题就按 `a` 保留，违反规则就按 `d` 删除，想稍后再看就按 `j` 跳过。

### 记录面板

选中一条评论，队列旁边的“记录”面板会显示其作者的记录。在面板顶部可以在“作者”和“页面”之间切换。地址 `Special:GlowThread/user/<name>` 和 `Special:GlowThread/page/<title>` 会打开某位作者的全部评论或某个页面上的全部评论，并显示记录。

作者记录显示：

- 账号：注册时间、编辑次数和封禁情况，并提供“封禁此用户”、“修改封禁”和“封禁日志”链接，
- “评论”：公开、待审核、已删除和已抹除的评论各有多少，
- “举报他人”：这个人提交了多少举报，其中多少成立、被驳回或仍未处理，以及已处理的举报中成立的比例。“查看 TA 未处理的 N 条举报”会列出这些举报，
- “其评论受到的处理”：最近的管理操作，
- “最近的评论”和“查看 TA 的全部评论”。

页面记录显示这个页面迄今发表的评论数，页面的评论状态及修改选项（可以填写理由），按状态分类的评论，“最近的处理”，“查看本页全部评论”和“本页的评论日志”。在从 FlowThread 迁移过来并开启了 `$wgGlowThreadLegacyCompat` 的维基上，“最近的处理”还可能列出 FlowThread 自己对这个页面的记录，例如开放或关闭评论（“开放评论”、“关闭评论”）、导入（“导入评论”）和删除。这些记录不显示评论编号。

处理难以判断的评论之前，先看看记录：一个只有已删除评论的新账号，和一位老成员的第一次举报，是不同的情况。

## 抹除

删除会隐藏评论，并且可以撤销。抹除是最终操作。它用于不能留在数据库中的内容，例如个人信息或违法内容。

- 只有已删除的评论可以被抹除，并且只有同时拥有 `glowthread-erase` 和 `glowthread-moderate` 的用户（默认为 `sysop` 用户组）可以操作。
- 在队列中，点击已删除评论上的“抹除…”。对话框会询问“永久抹除这条评论？”，并可选填理由。点击“永久抹除”确认。
- 文字被清空。评论中的作者会对所有没有 `glowthread-erase` 的人隐藏。作者此前关于这条评论的日志记录中，作者会对所有没有 `deletedhistory` 的人隐藏。这条评论引起的通知（回复、提及）会被隐藏。数据行会保留，所以回复和日志记录仍然有指向的对象。
- 作者会记录在 Special:Log/glowthread-private（“评论抹除日志”）中，只有拥有 `glowthread-erase` 的用户能查看。
- 每位管理员每小时最多抹除 30 条评论。`sysop` 用户组也不能绕过这个限制。
- 抹除无法撤销，也从来不会自动抹除任何内容。

## 页面状态

| 状态 | 标签 | 读者 | 管理员 |
|---|---|---|---|
| 开放 | “开放” | 所有人都可以发表和回复 | 全部功能 |
| 锁定 | “锁定” | 读者可以浏览和点赞，但不能发表或回复 | 仍然可以管理 |
| 关闭 | “关闭” | 读者看不到评论区。已有评论会保留 | 能看到评论，并有提示说明读者看不到 |

在评论区的“页面：”菜单中，或在 Special:评论管理 的页面记录中修改状态。每次修改都需要确认，并会记入日志。

讨论失控而你又想保留已有内容时，锁定页面。评论根本不适合出现在某个页面时，关闭页面。

页面保护不涵盖评论。拥有 `glowthread-post` 的用户仍然可以在受保护的页面上发表评论。要阻止页面上出现新评论，请锁定页面。

## 设置

**Special:评论管理/settings** 显示全站设置。管理员可以查看这些设置。修改需要 `glowthread-configure`（默认为 `sysop` 用户组）。

| 分区 | 设置 |
|---|---|
| “新账号审核” | “注册时长”（小时）和“免审核所需的公开评论数”。一句摘要会说明按当前的值新账号审核会如何处理。0 小时关闭新账号审核 |
| “举报” | “自动转入待审核的举报人数”（人）和“可选的举报理由” |
| “内容限制” | “评论长度上限”（字符）、“每条评论最多提及”和“重复内容间隔”（同一用户在同一页面再次发表相同文字前需要等待的秒数） |
| “功能” | “向所有人显示管理日志”：是否所有人都能查看评论日志，见[评论日志](#评论日志) |
| “频率限制” | 只供参考。它们在 `LocalSettings.php` 中设置 |

每个字段都显示允许的范围和默认值。站点管理员在 `LocalSettings.php` 中固定的设置显示为灰色，标注“已在 LocalSettings 中锁定”，不能在这里修改。

保存步骤：修改字段，点击“检查并保存”，核对更改列表，填写理由（必填，会显示在日志中），然后点击“保存更改”。“放弃更改”会丢弃未保存的更改。每次更改都会连同旧值和新值记入日志。

“自动转入待审核的举报人数”如何计算举报人：只计算已注册、不是作者本人、没有被封禁而无法在该处举报（全站封禁，或针对该页面或其命名空间的部分封禁）、自己能通过新账号审核、账号注册至少 7 天，并且至少有一条公开评论的用户。拥有 `glowthread-trusted` 的用户即使是新账号也会计入。临时账号无论注册多久都不计入，但它们的举报仍会进入审核队列。从 FlowThread 导入的举报不计入，除非同一用户再次举报这条评论。详见[配置](configuration.md#举报自动转入待审核)。

管理员已经保留的评论（已通过、已恢复，或举报已被忽略）不会再因举报自动转入待审核。之后的举报仍会出现在“被举报”分类中。如果撤销了那次操作，举报就可以再次让评论转入待审核。每次自动转入待审核都会记入 Special:Log/glowthread，操作者显示为“GlowThread”。这个用户名已被保留，任何人都无法注册。如果在安装 GlowThread 之前已有账号使用这个名称，该账号不会被接管，自动转入待审核的日志会改为显示操作者“Maintenance script”。与所有使用保留名称的账号一样，该账号无法再登录：重命名该账号即可让其主人恢复访问。

## 敏感词过滤

设置页面的“敏感词”部分用于编辑 **MediaWiki:GlowThread-filter** 上的规则。管理员可以在这里查看规则，但这个页面本身和所有界面页面一样是公开的：任何人都能读到规则，包括发垃圾信息的人。测试规则需要 `glowthread-configure`，编辑规则需要 `editinterface`。

- 每行一条规则。普通规则忽略大小写、全角形式和不可见字符，规则本身没有变音符号时也忽略变音符号。在词与词之间用空格分隔的语言中，普通规则按完整单词匹配：规则 `ass` 匹配“Ass!”、“a s s”和“a.s.s”，但不匹配“class”。多个单词的规则在单词之间有其他空格或符号，或者没有分隔时，也能匹配。这些整词规则紧挨着中文、日文或韩文文字时也能匹配，这些文字在拉丁单词前常常没有空格。在中文、日文、韩文、泰文、老挝文、高棉文和缅甸文中，普通规则在任意位置匹配，即使字符之间有空格、符号或 ASCII 标点也能匹配，但不会跨越换行、。和，等全角标点，或「」和“”等括号和引号。`/pattern/flags` 是正则表达式（标志 `i`、`m`、`s`、`x`）。以 `#` 开头的行是注释。
- 命中规则会让评论进入待审核。评论永远不会被拒绝。
- 无效的行会标出行号，并被忽略。
- 最多使用 2000 条规则。超出的第一行会标为“too-many-rules”，该行及其后的所有行都会被忽略。运行时间过长的正则表达式会提前停止。在一条评论上运行满四分之一秒后，剩下的正则表达式和整词规则不再运行。这两种情况下评论都会进入待审核，与规则运行失败时一样（“time-limit”）。
- 保存时，填写编辑摘要（必填），然后点击“保存敏感词”。这次更改是对该页面的一次普通编辑，有历史记录。“查看差异”显示差异。

**保存前先测试。** 把一条评论粘贴到“测试一段评论”中。结果会显示“会进入待审核：命中…。”及命中的行，或者显示“不会被拦下。”。测试与发表评论运行相同的检查，使用编辑框中的规则，无论是否已保存，所以你可以先用真实的例子试验新规则。

规则要具体，也要用无害的评论测试。普通规则匹配的范围比确切的词更广：

- 多个单词的规则也会跨越标点匹配，所以 `cheap coins` 会匹配“Is it cheap? Coins are rare”。
- 单词的字母分开写时也会匹配，例如首字母缩写，所以 `ass` 会匹配“A.S.S.”。
- 在中文、日文以及其他不用空格的文字中，普通规则会在更长的词内部匹配，因为这些文字没有用空格标出词的边界。
- 不带变音符号的规则也会匹配带变音符号的词，所以 `ano` 会匹配“año”。要只匹配某一种拼写，请写出变音符号：`lồn` 不会匹配“lớn”。
- 只拆开一处的词，例如“sp am”或“s-pam”，不会匹配 `spam`。要匹配其他拆法，请使用正则表达式，例如 `/\bs\W*p\W*a\W*m\b/i`。

需要更精细的控制时，请使用正则表达式。

完整语法见[配置](configuration.md#敏感词过滤)。

## 评论日志

Special:Log/glowthread（“评论日志”）列出每一次管理操作、页面状态更改、设置更改和作者自行删除，包括执行操作的管理员、评论编号和作者，以及理由。可以用“评论操作类型”按类型筛选。这个日志默认不在“主要公开日志”中显示，所以请按名称打开它，或者使用管理中心的“评论日志”链接。“向所有人显示管理日志”关闭期间，只有管理员和版主能查看它，而且这期间执行的操作永远不会显示在 Special:RecentChanges 或监视列表中，即使之后重新开启这个设置也一样。

新评论和举报不会记入日志。安装了 CheckUser 扩展时，每条新评论或举报会改为生成一条 CheckUser 记录。

被抹除评论的作者记录在 Special:Log/glowthread-private（“评论抹除日志”）中，见[抹除](#抹除)。在从 FlowThread 迁移过来的维基上，只要 `$wgGlowThreadLegacyCompat` 开启，FlowThread 的旧记录就在 Special:Log/comments（“FlowThread评论日志”）中。

## 封禁

- 受到任何封禁（包括部分封禁）的管理员都不能进行管理操作。队列仍然可以查看。
- 被封禁的读者不能发表、点赞或举报。部分封禁只在它覆盖的页面或命名空间上生效。
- 没有“只禁止评论”的封禁。要阻止某人评论，可以禁止其编辑，或对相关页面或命名空间使用部分封禁。作者记录中有指向 Special:Block 的链接。
